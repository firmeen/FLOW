# Privacy & PDPA

Controls how FLOW identifies its privacy role, documents processing activities, communicates notices, contracts for data processing, manages consent, handles data-subject requests, governs subprocessors, retains/deletes data, and responds to privacy incidents.

## Operating principle
Privacy documentation must match the actual architecture and business purpose. FLOW may act differently across activities—for example controller for its own account administration or marketing, and processor for merchant end-customer data when the merchant determines the purpose.

## End-to-end chain
```text
Processing purpose identified → role determined → data inventory/ROPA → notice/contract/lawful basis → system/security controls → subprocessor/transfer review → operational use → rights/consent/retention controls → incident handling → deletion/anonymization/archive evidence
```

## Control rule
Do not copy a privacy notice or DPA promise that the system cannot actually perform. Data-location, deletion, backup, incident timing, audit, and subprocessor commitments require technical validation.
