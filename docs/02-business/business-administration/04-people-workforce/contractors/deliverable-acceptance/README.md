# Contractor Deliverable Acceptance

Creates objective evidence that a milestone/deliverable met agreed acceptance criteria before payment or project closure.

## Required fields
SOW/milestone ID, deliverable description, repository/PR/release/design/source link, acceptance criteria, tests/review performed, defects/exceptions, status (`ACCEPTED`, `REJECTED`, `CONDITIONALLY ACCEPTED`), approver, date, remediation items, and payment milestone released.

## Workflow
```text
Deliverable submitted → completeness check → acceptance tests/review → defects recorded → contractor remediation if needed → acceptance decision → evidence signed/recorded → finance payment trigger → archive
```

## Control rule
“Looks okay in chat” is insufficient for material contracted work where payment, IP, or handover depends on acceptance.
