# Privacy Templates

Holds safe baselines for privacy notices, DPA schedules, ROPA/data inventory, consent records, data-subject request cases, retention/deletion records, subprocessor reviews, and breach-assessment worksheets.

## Design rule
Every template must map to real data flows and actual system capability. Fields for role (controller/processor), purpose, data subjects/categories, systems/vendors, retention, rights, incidents, transfers, and security should not be generic filler.

## Review triggers
New product data flow, new vendor/subprocessor, new customer DPA requirement, cross-border/data-location change, new marketing purpose, security architecture change, retention change, or privacy incident.

Do not encode promises such as immediate backup deletion or impossible notice timing without technical validation.
