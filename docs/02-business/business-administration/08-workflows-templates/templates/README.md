# Templates

Stores reusable safe baselines for business documents. Templates are not executed records and must include operating instructions so users know when and how to use them.

## Template design standard
Every material template should explain: purpose, trigger, owner, required inputs, mandatory fields/clauses, negotiable fields, prohibited edits, reviewer/approver/signatory, professional-review triggers, downstream register/system updates, numbering/versioning, retention, and completion evidence.

## Lifecycle
```text
Need → owner → draft → specialist review → approval → version/effective date → published template → usage monitoring → issue/change trigger → new version → old template superseded/archive
```

## Storage rule
Use Git for safe templates and instructions only. Customer/vendor-specific executed copies, identity data, bank/payroll data, and confidential professional advice live in controlled storage.

## Folder rule
The subfolders classify templates by operating function rather than keeping one large undifferentiated template directory.
