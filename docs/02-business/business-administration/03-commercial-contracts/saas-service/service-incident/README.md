# Service Incident Documentation

Links technical incidents to customer commitments, SLA calculations, communications, security/privacy assessment, credits, and corrective actions.

## Incident record
Incident ID, detection source/time, affected services/customers, severity, start/mitigation/restoration times, symptoms, technical cause, customer impact, communication timeline, SLA relevance, security/privacy relevance, decisions, workaround, final remediation, and postmortem actions.

## Workflow
```text
Detection → triage/severity → contain/mitigate → customer/SLA/security/privacy obligations checked → communications → restoration → monitoring → root-cause analysis → credits/remedies if applicable → corrective actions → evidence archive
```

## Control rule
Do not write a public/customer postmortem that contradicts preserved technical evidence. Legal/privacy/security review may be needed for sensitive incidents.
